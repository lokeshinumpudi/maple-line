# Local scene inspector

`apps/game/src/agent/scene-inspector.js` exposes a compact Three.js context and editing API for local development. The parent app installs it only behind its development guard. It does not provide a server, network endpoint, arbitrary JavaScript execution, or automatic source-file edits. Changes made through the inspector are temporary and disappear on reload.

## Integration

From `/Users/lokeshinumpudi/Desktop/maple-line`, run `pnpm dev` to start the `@maple-line/game` app through Turborepo. The import below is relative to `apps/game/src/main.js`. Production output is generated by `pnpm build` in `apps/game/dist/`; `pnpm build:readable` writes unminified output with source maps to `apps/game/dist-readable/`.

```js
import { installSceneInspector } from './agent/scene-inspector.js';

if (import.meta.env.DEV) {
  installSceneInspector({
    THREE,
    scene,
    renderer,
    camera,
    train,
    getState: () => ({ ...gameStore.snapshot(), routeLength: trackLength }),
    actions: {
      camera: (value) => selectCamera(value),
      weather: (value) => selectWeather(value),
      pause: (value) => setPaused(value),
    },
  });
}
```

The callbacks above are integration examples, not functions defined by this module. Parent callbacks must validate their payloads and use the same update paths as the game controls. Available action names are `camera`, `weather`, `timeOfDay`, `location`, `drive`, `pause`, `autopilot`, and `mode`; an action works only if the parent supplies its callback. Camera values include `scenic`, `follow`, `cab`, and `orbit`. Player door, emergency-brake, HUD, and AI-life controls do not currently have inspector action callbacks.

Name important scene objects when creating them, for example `river`, `terrain-gorge`, `train-front`, `station-momiji`, `platform-momiji`, `sun`, and `forest-east`. Exact names should be unique. UUIDs remain available for unnamed objects and duplicate names.

## Context and diagnosis

```js
mapleWorld.snapshot(); // Game, active camera, render counters, named entities
mapleWorld.find('train'); // Name, type, UUID and ID search; up to 150 results
mapleWorld.inspect('train-front'); // Bounds, transform, material and geometry counts
mapleWorld.raycast(0, 0); // Up to 20 hits at the centre of the screen
mapleWorld.audit(); // Camera/train overlap, invalid transforms, depth flags
```

Ray coordinates run from -1 to +1. The bottom-left corner is `(-1, -1)` and the top-right is `(1, 1)`. Hits include instance IDs where applicable. The summary contains geometry counts rather than large position or index arrays. Renderer counters describe the latest frame and are not timing benchmarks.

To investigate a blocked driver view, pause the game, select driver mode, collect `snapshot()` and `audit()`, then inspect the first hit from `raycast(0, 0)`. The train-bounds check is a coarse warning: a camera inside the overall train bounds may still have a valid windshield view. Confirm with a screenshot and motion checks.

Depth diagnostics report material settings that can affect overlap rendering. They do not prove or exclude coplanar z-fighting. Inspect the relevant bounds and materials alongside the visible defect before changing geometry. Individual instances are identified by picking, but this version edits whole objects, not individual instance matrices.

## Controlled changes

```js
mapleWorld.set('camera', 'cab'); // Actual accepted values are defined by parent callbacks
mapleWorld.set('weather', 'snow');
mapleWorld.patchObject('river', {
  position: [0, -0.05, 0],
});
mapleWorld.patchObject('station-momiji', {
  visible: false,
});
mapleWorld.patchObject('rock', {
  material: { color: '#8b9683', roughness: 0.9, metalness: 0 },
});
mapleWorld.undo(); // Undo the most recent object patch
```

Object patches accept only local `position`, Euler `rotation` in radians, positive `scale`, boolean `visible`, and supported `material` fields. Material colors require six-digit hex. Numeric fields are finite and range-checked before any edits. Material edits clone the target material so other objects sharing it do not change. `undo()` restores the previous transform, visibility and material, disposing the temporary cloned material.

Object patches require an object UUID, numeric ID, or unique exact name; substring matches cannot change objects. `undo()` covers object patches only, not gameplay actions such as location or weather. Objects animated by the game may overwrite a transform edit on the next frame; pause or change the source parameter through a parent action instead.

To retain a useful change, copy it into the appropriate world-generation or material source code and verify it after reload. The inspector itself does not write files. The development panel can save a snapshot, but agents can read the API directly. The [WebMCP integration](WEBMCP.md) exposes structured game tools and a page-local fallback; native discovery was verified in an isolated Chrome for Testing session, while Chrome Agent on port 9229 currently uses the fallback.
